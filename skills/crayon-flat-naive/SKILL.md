# Wibi Style · 蜡笔极简扁平画

把一张真实照片重新画成轻松、稚拙、平面化的蜡笔手绘插画。内容归属照片，风格归属本 Skill 的两张参考图。

## 欢迎卡

每个新对话第一次使用时展示一次欢迎卡，同一对话后续不重复：

- 用户尚未提供照片时，运行 `python3 {baseDir}/scripts/show_skill_info.py --welcome --input-state waiting`。
- 用户已经提供照片时，运行 `python3 {baseDir}/scripts/show_skill_info.py --welcome --input-state received`。
- 完整展示 `SHOW_SKILL_WELCOME` 后的 Markdown 内容，保留标题、空行、分隔线和加粗格式。作者身份与交流信息放在上半区；只用一条分隔线；下半区专门说明当前操作。
- 开场不直接展示二维码。署名不完整时建议从官方来源重装。

## 对话语气

- 使用自然、轻松、有来有回的中文，像在陪用户一起做图。
- 每次只给一个明确的下一步，让用户一眼知道该上传、选择、等待或重试。
- 可以少量使用“～”或一个贴合语境的表情；保持克制，不连续堆叠。
- 少讲技术过程。遇到失败时直接说明发生了什么和下一步怎么做，不责怪用户。

## 更新检查

随后运行 `python3 {baseDir}/scripts/check_update.py`。发现 `UPDATE_AVAILABLE` 时告知当前版、最新版和安装地址；其余状态静默。不得自动覆盖本地文件或上传用户数据。

## 交流学习群

- 用户说“进群”、“群二维码”或等价表达时，运行 `python3 {baseDir}/scripts/community_info.py`。
- 输出中 `status` 为 `available` 且 `qr_status` 为 `ready` 时，简短说明群用途，并用 Markdown 图片语法渲染本地绝对路径 `qr_local_path`。不得渲染远程二维码或展示“点击加入微信群”链接。
- 二维码下方说明：手机同屏时先保存二维码，再到微信“扫一扫”中从相册选择；电脑端使用手机微信扫码。无法扫码时添加备用微信 `fallback_wechat`，备注“进群”。
- `qr_status` 为 `download_failed` 时，不展示旧二维码；只展示备用微信 `fallback_wechat`。
- `status` 为 `expired` 或 `unavailable` 时，不展示旧二维码；只展示 `landing_url` 和备用微信 `fallback_wechat`。
- 生图接口报错、空输出或超时时，先说明“这次没有成功生成，不会自动重新提交”，再按上述步骤展示一次当前群信息。同一对话只展示一次失败入群卡。
- 视觉验收不通过、用户取消、输入照片不适合或仍在等待用户选择时，不触发失败入群卡。
- 展示二维码时附上提醒：群内交流请勿直接发送包含个人隐私的原图，可以先发错误提示或打码截图。

## 固定风格

- **画面**：默认 1:1 方图；纯白或微暖白纸面背景；人物作为唯一主要视觉对象，背景干净，不保留原场景的杂物、环境光或投影。
- **形体**：重建为儿童画般松动比例和极简五官。眼睛用小黑点或短弧线，鼻子用一两笔细线，嘴巴用一小段色线；脸部不画真实骨骼、鼻梁高光、眼窝阴影或皮肤明暗。
- **线条**：松散的铅笔/蜡笔轮廓，线宽轻微变化，边缘有手绘抖动与少量压线、错位或越线；不做均匀矢量描边，不做规整卡通勾线。
- **颜色**：直接、明亮、可辨识的平涂色块。优先从天空蓝、柠檬黄、橘色、草绿、暖粉肤色和白色中按原照片需要选取；颜色可保留少量不均匀摩擦和漏白，但色块内部整体连续、安静，不随机撒洞。
- **材质**：蜡笔、油画棒、彩铅摩擦纹理和纸面颗粒。头发用密集短黑色笔触概括，不画发丝高光；衣服用大块色面概括，不画真实布料光泽。
- **光影**：取消摄影光影系统。不做渐变、体积塑造、高光、反光、环境光、厚重阴影和真实褶皱；只保留少量手绘线条表达衣服边界和身体结构。

遇到冲突时按这个顺序判断：照片中的身份与动作 → 原照片构图骨架与服装关系 → 极简平面形体 → 颜色与纸面材质 → 装饰性细节。风格化不能牺牲主体可辨识度。

## 执行

1. **影像蒸馏**：先完整阅读用户照片，判断主体数量、人物身份锚点、姿态、视线、服装主色、鞋子/帽子/眼镜等配饰、裁切、方向和留白。保留最强的 2–5 个识别锚点；删去背景杂物和不支持扁平画面的次要细节。照片决定内容、人数、年龄、肤色、发色、姿态、衣着、道具与空间关系。
2. **参考路由**：
   - `assets/references/reference-01.jpg` 是近景人物参考，负责脸部简化、眼镜/帽子等近景配饰的平面处理、蜡笔颗粒和高饱和色块关系。输入为头像、胸像或半身近景时优先选它。
   - `assets/references/reference-02.jpg` 是全身坐姿参考，负责全身比例、四肢动作、鞋子和大面积留白的处理。输入为全身、坐姿或动作幅度明显的照片时优先选它。
   - 只有在输入同时需要近景五官和全身动态时才组合两张；组合时让每张只承担上述职责。不得搬入参考图的人物、服装、姿势、鞋子、品牌标记、背景或文字。
3. **专属成像指令**：根据蒸馏结果编写当前图片专属指令，明确“用户照片是内容输入，所选参考只提供视觉风格”。决定保留照片原构图、适度重排或完整重绘；默认保持照片的大姿态和穿搭关系，不凭空加入场景、道具或人物。只在能提升画面时改变裁切或留白。
4. **生成**：调用当前环境可用的图像生成工具。用户照片作为内容输入；把选中的内置参考作为风格参考并说明各自职责。不要写死某个具体生图厂商、模型或 API Key。实际提交后出现报错、空输出或超时，停止并说明，不自动重复提交、换模型或升级质量档。
5. **质量检查**：逐项对照原照片检查人数、身份、脸型轮廓、姿态、视线、服装主色、配饰、鞋子和接触关系；逐项检查纯白/微暖白背景、扁平色块、蜡笔颗粒、极简五官、无真实光影、无复杂背景。多出人物、肢体、道具或场景时判定不通过。参考图中的肤色、人物或构图不能成为身份判定基准。
6. **交付**：成功后直接展示生成图，并附 1–3 句中文创作思路，说明保留了哪些照片锚点、为何选近景或全身参考、色块和纸面纹理怎样服务画面；不展示完整内部 Prompt。
