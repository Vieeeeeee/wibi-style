# Wibi Style · 框景漫画

## 运行顺序

每一步只读它对应的文件，读完执行再进下一步：

1. 新对话第一次使用：按 [references/community.md](references/community.md) 展示欢迎卡、检查更新；进群、生成失败后的提示也按它处理。
2. 收到照片：读 [references/distill.md](references/distill.md)，判断什么才算特写，给出 A、B、C 三个文字局部候选并推荐一个，停下等用户选。
3. 用户选定局部：读 [references/frame.md](references/frame.md)，选参考图、锁定真实裁切、选规则框形，按两步生成完成画面，处理越框、画风与颜色。
4. 生成后：读 [references/checks.md](references/checks.md)，写当前照片的生图指令、跑硬检查、按分层做安全收尾或定向重做；批量任务逐张走同一套。
5. 交付：按下面「给用户的输出」展示。

## 核心目标

从用户照片中找到一个值得被放大的局部事件，主动裁掉大部分人物和环境，只保留最有张力的形状、接触、遮挡或装饰关系。把这个局部画成小框中的大特写，再让小框落在大面积纯色留白里。默认主动寻找一处自然越框，让局部事件从窗口中生长到留白区域；同时主动寻找一处框内外同色连接，让边界在共享色接触处自然消失。

始终记住两个尺度：

- 框景在整张画布里很小；
- 被选中的细节在框景内部很大。

小框里出现完整头像、完整半身或完整全身，通常说明取景仍停留在人物层面，需要重新蒸馏。

## 触发与生成次数

用户首次上传一张照片并要求“测试”“生图”“用这个风格做一下”或直接调用本 Skill 时，先给出 A、B、C 三个文字局部候选并推荐 A，不调用生图工具。输出候选后停下，等待用户选择。

用户回复 A、B、C，或用自然语言明确选中其中一个局部后，再生成一张结果。用户说“你决定”“直接做”“按推荐来”或明确要求跳过选择时，采用推荐的 A 继续生成。

用户只给反馈时，更新判断逻辑并停下，等待下一次明确测试。

用户明确授权连续自测、批量验证或持续优化时，按授权数量逐张生成、逐张检查并保留版本。

使用当前运行环境已经可用的图像生成工具或模型，优先使用无需用户额外配置的内置能力。某个工具不可用时继续寻找当前环境中的其他生图能力；确认没有任何生图能力后，请用户添加或启用可生图工具或模型。

## 输出尺寸

所有构图卡和最终成图统一使用 **1440×2560 像素、9:16、PNG**。本 Skill 把 1440×2560 作为 2K 竖图交付标准。

生图时明确要求 9:16 竖图，并保留工具返回的最高分辨率原图。当前生图能力无法直接锁定具体像素时，先完成内容与画风，再按以下方式收尾：

- 始终从最高分辨率生成结果开始处理；
- 裁切、框外纯色整理和边缘清理都在原始尺寸完成；
- 最后一次性缩放或放大到 1440×2560，不经过中间尺寸；
- 全流程保留 PNG，不在中间步骤转成 JPEG；
- 结果大于目标尺寸时只做一次高质量缩小；
- 结果小于目标尺寸时只做一次高质量放大，尽量保住已有像素，但不把放大后的尺寸误认为新增了原图细节；
- 交付前读取文件实际尺寸，只有精确等于 1440×2560 才通过。

## 什么才算特写

合格特写需要同时满足以下判断：

1. 能用“一个具体局部 + 一个关系”描述，例如“手指拨开头发露出耳饰”“牙刷触碰嘴角”“手掌挡住一只眼睛”“膝盖与鞋穿过框线”。
2. 裁切后仍保留原照片独有的辨识线索，换一张普通人像无法得到同样的画面。
3. 主要细节占满框内的大部分面积，至少有一个人物边界被主动裁掉。
4. 视线首先落在局部事件上，随后才意识到人物身份。
5. 去掉这个局部后，画面会失去成立理由。

遇到以下结果时，回到影像蒸馏重新选点：

- 完整脸居中，只更换了漫画画风；
- 半身或全身被整体缩进一个小框；
- 主要观看内容只能描述为“一个人在看镜头”；
- 局部在缩略图里小到看不清接触、遮挡或装饰关系；
- 框形和底色很醒目，框内没有值得细看的内容。

## 给用户的输出

新照片尚未选择局部时，只输出 A、B、C 三个文字候选、推荐理由和选择提示，然后停下。此时不调用生图工具，不展示构图草图。

用户选定局部后，先展示生成图，再用两三句话写“创作思路”，说明放大了原片中的哪个局部事件、为什么值得看，以及框形和颜色怎样服务这个局部。不要展示内部候选比较或完整生图指令。
