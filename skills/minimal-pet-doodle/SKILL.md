# Wibi Style · 宠物极简线条

## 欢迎卡

每个新对话第一次使用时展示一次欢迎卡，同一对话后续不重复：

- 用户尚未提供照片时，运行 `python3 {baseDir}/scripts/show_skill_info.py --welcome --input-state waiting`。
- 用户已经提供照片时，运行 `python3 {baseDir}/scripts/show_skill_info.py --welcome --input-state received`。
- 完整展示 `SHOW_SKILL_WELCOME` 后的 Markdown 内容，保留标题、空行、分隔线和加粗格式。
- 开场不展示二维码。署名不完整时建议从官方来源重装。

## 对话语气

- 使用自然、轻松的中文，每次只给一个明确的下一步。
- 少讲技术过程。失败时说明现状与下一步，实际提交失败后停止等待用户决定。

## 更新检查

随后运行 `python3 {baseDir}/scripts/check_update.py`。发现 `UPDATE_AVAILABLE` 时告知当前版、最新版和安装地址；其余状态静默。

## 交流学习群

- 用户说“进群”、“群二维码”或等价表达时，运行 `python3 {baseDir}/scripts/community_info.py`。
- 输出中 `status` 为 `available` 且 `qr_status` 为 `ready` 时，用 Markdown 图片语法渲染本地绝对路径 `qr_local_path`。不得渲染远程二维码。
- 二维码下方说明手机同屏时先保存二维码，再到微信“扫一扫”中从相册选择；电脑端使用手机微信扫码。无法扫码时展示 `fallback_wechat`，备注“进群”。
- `qr_status` 为 `download_failed` 时只展示 `fallback_wechat`；`status` 为 `expired` 或 `unavailable` 时只展示 `landing_url` 和 `fallback_wechat`。
- 生图接口报错、空输出或超时时，先说明“这次没有成功生成，不会自动重新提交”，再展示一次当前群信息；同一对话只展示一次失败入群卡。
- 视觉验收不通过、用户取消、输入照片不适合或仍在等待用户选择时，不触发失败入群卡。
- 展示二维码时提醒：群内交流请勿直接发送包含个人隐私的原图，可以先发错误提示或打码截图。

## 读取照片

先完整查看用户照片，确认宠物种类、数量、可见身体范围、头部方向、视线、姿态、身体曲线、动作关系、毛色分区和画面重心。选出一个最能代表当前照片的动作锚点，例如跃起、回头、伸爪、蜷卧、仰头或贴近镜头。

用户照片决定画什么。只保留照片真实可见的宠物、身体、动作、毛色和必要支撑关系。照片只露出头部时采用头像范围；照片包含完整动作时保留动作所需身体曲线。多只宠物只在数量和关系都清楚时一起画。

## 风格机制

完整读取 `references/style-prompt.md`，把它作为当前成图的风格规则。本款没有运行参考图，生成时只携带用户照片。

成图遵循以下顺序：

1. 用一个动作轮廓锁定姿态和视觉重心。
2. 用开放轮廓与不完整手势形概括身体，留下自然断点。
3. 用 1–3 组轻重不匀的黑线表现主要动作方向。
4. 用 1–3 个微小黑色记号概括眼睛、鼻子和嘴。
5. 用一小块干性彩铅或蜡笔色斑呼应真实毛色，保留纸纹、越界和未填满区域。
6. 使用纯白、奶油白或浅米色纸面，让连续留白成为画面主体。

线条要像第一次落笔的试探性儿童速写，保留轻微抖动、断点、浓淡变化和笨拙比例。构图保持原照片的动作方向与偏置关系，主体周围留出宽阔呼吸空间。最终画面只含宠物涂鸦和纸面。

## 生成与检查

为当前照片写一份专属生图指令，说明必须保留的动作、可见身体范围、头部与视线方向、毛色区域、留白比例和一块彩色涂抹。使用当前环境可用的图像生成能力生成一张 1:1 图片。实际提交后报错、空输出或超时时停止，不自动重复提交。

生成后检查：

- 宠物种类、数量、姿态、动作方向、视线和可见身体范围与照片一致；
- 主轮廓开放且简洁，五官保持少量微小记号；
- 只有一块主要色斑，颜色与真实毛色有关系；
- 大面积纸面留白连续，主体位置保留照片的动作重心；
- 画面没有文字、水印、边框、复杂背景、完整上色和精细商业插画感。

通过检查后展示成图，并用一至三句中文说明保留了哪个动作锚点与毛色关系；不公开完整内部 Prompt。
