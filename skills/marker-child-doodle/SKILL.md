# Wibi Style · 马克笔童画

## 风格目标

把一张真实照片直接画成像从儿童速写本上撕下来的马克笔页：人物或动物关系清楚，形体夸张但不精致，主要色块填得干净完整，轮廓和色块边缘保留手涂的不齐。

固定视觉机制：

- 真实照片决定内容，内置参考图只决定画法。禁止把参考图的人、球衣、球、号码、队徽、文字或签名带入结果。
- 画面是 1:1 方形白纸或黑底马克笔页；全图控制在石板灰蓝线、照片人物肤色、一个服装主色和黑色以内。
- 头大、身小、脖子短，手是没有关节的团块，脸只保留粗眉、方块眼、短鼻和短嘴；夸张服务于童画感，不能牺牲原图主体数量、动作和互动关系。
- 轮廓粗、钝、抖、粗细不匀，局部有积墨和轻微错位；整体保持连续，只出现少量自然断口，不做成均匀虚线。
- 主要色块内部尽量填满，减少白点、白洞和白丝；手绘感集中在外围边缘、少量错位和少量溢出。白色主要来自色块之间和画面周围的有意识留白。
- 环境通常删除，只保留人物正在触碰、使用或明确指向的一两件物件。坐姿保留一条桌沿或支撑面线；半身照片不补腿脚；宠物同框时人和动物都要画。
- 默认右下角加入潦草英文签名 `wibi`。用户指定签名内容时，替换文字但保持一笔或少数几笔、挤压、省略、歪斜、带拖尾的手势。

- 用户已经提供照片时，运行 `python3 {baseDir}/scripts/show_skill_info.py --welcome --input-state received`。

- 开场不直接展示二维码。署名不完整时建议从官方来源重装。

随后运行 `python3 {baseDir}/scripts/check_update.py`。发现 `UPDATE_AVAILABLE` 时告知当前版、最新版和安装地址；其余状态静默。不得自动覆盖本地文件或上传用户数据。

## 交流学习群

- 用户说“进群”“群二维码”或等价表达时，运行 `python3 {baseDir}/scripts/community_info.py`。
- 输出中 `status` 为 `available` 且 `qr_status` 为 `ready` 时，说明群用途，并用 Markdown 图片语法渲染本地绝对路径 `qr_local_path`。不得渲染远程二维码或展示“点击加入微信群”链接。
- 二维码下方说明：手机同屏时先保存二维码，再到微信“扫一扫”中从相册选择；电脑端使用手机微信扫码。无法扫码时添加备用微信 `fallback_wechat`，备注“进群”。
- `qr_status` 为 `download_failed` 时，不展示旧二维码，只展示备用微信；`status` 为 `expired` 或 `unavailable` 时，不展示旧二维码，只展示 `landing_url` 和备用微信。
- 生图接口报错、空输出或超时时，先说明“这次没有成功生成，不会自动重新提交”，再按上述步骤展示一次当前群信息。同一对话只展示一次失败入群卡。
- 视觉验收不通过、用户取消、输入照片不适合或仍在等待用户选择时，不触发失败入群卡。
- 展示二维码时提醒：群内交流请勿直接发送包含个人隐私的原图，可以先发错误提示或打码截图。

## 执行流程

### 1. 影像蒸馏

先完整查看用户上传的真实照片，再判断：

- 主体数量、人物或动物身份、姿态、动作、视线、头发轮廓、服装主色和配饰；
- 互动关系，例如手与食物、手与杯子、人与宠物、人物与桌沿的接触点；
- 原图是近景、半身还是全身，主体在画面中的位置，以及动作或视线朝向哪一侧；
- 哪些环境可以删除，哪些物件必须保留，否则动作会失去意义；
- 当前照片最容易被 Q 版化破坏的内容，例如宠物被删掉、半身被补出腿、互动物件被替换或人物被参考图替代。

原图拍到哪里就画到哪里。先锁定原图中的内容关系，再允许夸张头身比、手和五官；不要用风格参考修正人物身份、肤色、服装、道具或动作。

### 2. 参考图职责与携带方式

本 Skill 内置一张 `assets/references/reference-01.jpg`，它是通用马克笔画法锚点：提供石板灰蓝粗轮廓、黑色几何头发、四色平涂、白纸留白、手涂边缘和潦草签名的手势。

每次生成都把用户真实照片作为内容输入，并携带这张参考图作为风格参考。向图像模型明确说明附件角色，不依赖上传顺序：照片决定画谁和画什么，参考图只决定怎样画。不要把用户过去的生成图、Q 版成图或失败图作为底图，也不要先对照片做一次风格化再处理第二次。

### 3. 实景拼贴与风格成像

根据蒸馏结果，为当前照片现场编写一份专属生图指令：

1. 先锁定人数、主体、姿态、裁切、互动道具和关键颜色；
2. 决定白纸还是黑底：明亮、背景干净的照片保留白纸留白；昏暗、夜景或舞台光照片采用整幅手涂黑底，并把主体推向一侧；
3. 删除环境，但保留让动作成立的物件和一条必要的支撑面线；
4. 应用夸张 Q 版比例、四色平涂、完整色块和粗糙外轮廓；
5. 保留动作或视线朝向一侧的开放空间，不强行把主体塞满画面；
6. 根据用户要求决定签名，未指定时使用潦草 `wibi`。

让模型知道“内部色块处处留白”是错误方向，“轮廓完全闭合且粗细均匀”也是错误方向；同时控制溢出只发生在少数有意义的边缘，避免重新变成脏乱儿童涂色。

### 4. 生图与检查

使用当前环境可用的图像生成能力生成一张 1:1 结果，优先使用无需用户额外配置的能力。一次请求只处理一张真实照片；失败、空输出或超时停止，不自动重试、换模型或把生成图拿来二次处理。

生成后按以下顺序检查：

- 内容：主体数量、动作、视线、服装、配饰和互动道具是否来自用户照片；
- 关系：宠物是否保留，手是否真的碰到食物、杯子、桌沿或其他关键物件；
- 画幅：半身没有凭空补腿，全身没有被不必要地截断，留白方向与动作方向协调；
- 风格：粗糙石板灰蓝轮廓、完整平涂色块、少量边缘错位、无渐变和无精致数码线稿；
- 身份隔离：没有出现参考图人物、球衣、号码、球、队徽、文字或别人的签名；
- 签名：默认是潦草 `wibi`，不能变成工整字体或清晰 Logo。

通过检查后直接展示图片，并附一至三句中文创作思路；不公开完整内部 Prompt。核心检查失败时说明具体问题，等待用户明确要求后再重做。
