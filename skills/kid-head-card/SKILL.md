# Wibi Style · 童年大头卡贴

两种玩法共用同一个视觉骨架：**一颗完整的头悬浮在干净纯色底上，没有脖子、肩膀和身体，边缘像一张精心切割的贴纸。** 区别在于原片是什么，以及往哪个方向做。

| | 甜版·钻牙萌娃 | 酷版·童年酷照 |
| --- | --- | --- |
| 输入 | 儿童老照片 | 当代自拍（多为成年人） |
| 做什么 | 重拍式重建成明亮可爱的现代儿童棚拍，露齿时做满钻牙 | 把本人反推成 5–8 岁，加潮童装饰 |
| 背景 | 五选一，默认白色 | 固定浅灰白 |

- 使用自然、轻松、有来有回的中文，像在陪用户一起做图。
- 每次只给一个明确的下一步，让用户一眼知道该上传、选择、等待或重试。

- 少讲技术过程。遇到失败时直接说明发生了什么和下一步怎么做，不责怪用户。

## 分路：先读图，再说一句

拿到照片先自己看，不要上来就问。判断依据是**照片本身的年代痕迹和主体年龄**，不是文件名或用户措辞：

**走甜版**——照片同时具备多数以下特征：褪色或偏棕灰、昏黄室内光、粗胶片颗粒、旧闪光灯的硬光斑、暗角、折痕或扫描痕迹，且主体本来就是儿童。

**走酷版**——照片是清晰的当代手机拍摄：曝光正常、色彩干净、可能带美颜或滤镜，主体是成年人或青少年。

判断完直接开工，同时用一句话交代走向并留口子，例如：

> 这张看着是当代自拍，我按「童年酷照」做——把你反推成 5–8 岁的样子。想要另一种（老照片变钻牙萌娃）随时说。

**真正需要问的只有一种情况**：清晰的当代照片但主体已经是儿童。这时两条路都成立——保持原年龄做钻牙萌娃，或者当作已经是童年照直接做酷版装饰。给这两个选项让用户选，不要自己猜。

用户明确说了要哪一版时，直接照办，不再判断。

## 甜版·钻牙萌娃

读取 [mode-sweet-prompt.md](references/mode-sweet-prompt.md) 组合生成指令，背景选项读 [background-options.md](references/background-options.md)。

第一次生成前先询问背景，给五个选项：A 默认白色（推荐）、B 复古大波点、C 柔和双色渐变、D 蜡笔手绘小星星、E 柔粉纯色。用户说「默认」「都行」「你决定」或没提彩色背景时，一律用 A，不得自行改选彩色。

固定结果：

- 只有一颗完整人头、头发和头部配饰；没有脖子、肩膀、锁骨、衣服、手或身体。
- 原图画框内可见的头发、发辫、发揪与配饰完整进入成品；原图已出框的部分才允许裁切。
- 保持原片嘴部开合和表情。明显露齿时才在每颗可见牙面密铺多颗小钻；闭嘴或几乎不露齿时不加钻、不造齿。
- 老照片只提供人物身份和头部特征，不沿用原片的暗沉曝光、昏黄环境光、褪色、棕灰色调、旧闪光灯质感或年代感。人物必须重建为明亮、光鲜、可爱的现代儿童棚拍。
- 一次只使用一种背景，不生成四宫格或方案集。

## 酷版·童年酷照

读取 [mode-cool-prompt.md](references/mode-cool-prompt.md) 组合生成指令。这一版不询问背景，固定浅灰白。

固定结果：

- 年龄落在 5–8 岁：颅顶偏大、婴儿肥盖住颧骨、下颌线柔软、乳牙细小。看上去像 9 岁以上就是错的。
- 眼型完全照搬本人——细长保持细长、单眼皮保持单眼皮。**不允许为了可爱把眼睛画圆、放大或加双眼皮**，这是最容易丢辨识度的一步。
- 一律给微笑，微露上排乳牙，不沿用原照片的表情。
- 发型跟原图走，要有长度和重量，额前碎发盖住额头上半、两侧盖过耳廓上缘；绝不寸头。发色回到天生黑或深棕，染发不带入。
- 装饰按人物性别气质分档，不混用：男孩用黑色墨镜歪架头顶、银色耳饰、无色与冰蓝水钻星芒，不用糖果色花朵；女孩用糖果色小花、心形、星星与彩色亮片。每张至少 8–15 粒水钻星芒加 2–4 个造型件，不允许为零。
- 装饰要明显是塑料贴纸质感，与写实皮肤形成反差；不对称簇集在一侧脸颊外围。
- 原照片本人戴的耳环、帽子、发夹可以带进成品，**材质、颜色、款式一并保留**，只按儿童尺寸缩小。但眼镜不许戴在小孩脸上遮住眼睛。
- 长发时整体缩小，发梢完整落在画内不被裁；发丝空隙直接透出背景，不透出脖子和衣服。

## 执行

1. 读原片，按上面的分路判断走哪一版，说明走向。
2. 按对应模式的参考文件组合本次生图指令；甜版先确认背景。
3. 使用当前运行环境已经可用的图像生成工具或模型，每次生成 1 张 1:1 结果，优先使用无需用户额外配置的内置能力。某个工具不可用时继续寻找当前环境中的其他生图能力；确认没有任何生图能力后，请用户添加或启用可生图工具或模型。
4. 按下面的验收逐条检查。未通过时报告具体问题，不自动重试。

成功生成后直接展示图片，并用一至三句中文说明这一张保留了哪些人物特征、为什么走这一版；不公开完整内部 Prompt。

## 验收

两版共同：

1. 是否严格只有大头，下巴以下直接进入背景，没有脖子、肩膀和衣服。
2. 头发、帽子与配饰轮廓是否完整落在画面内、没有被画布边缘切到。
3. 边缘是否干净锐利、无投影，像一张贴纸。
4. 是否无文字、水印、对比图、分屏和多余物件。

甜版另查：

5. 原人物是否可辨认；原片露齿时是否是「每颗牙面密铺多颗小钻」而非每齿一颗大钻、牙钉或牙套；原片闭嘴时是否未造齿。
6. 人物是否已重建为明亮通透的现代棚拍，而不只是把老照片修清晰。
7. 背景是否只用了一种选项。

酷版另查：

8. 眼型是否仍是本人的形状，有没有被画成通用娃娃眼。
9. 年龄是否真的在 5–8 岁，婴儿肥够不够。
10. 装饰是否按性别分档、没有混用，数量是否达到下限。
11. 小孩脸上有没有被戴上眼镜。

## 交流学习群

- 用户说「进群」、「群二维码」或等价表达时，运行 `python3 {baseDir}/scripts/community_info.py`。
- 输出中 `status` 为 `available` 且 `qr_status` 为 `ready` 时，简短说明群用途，并用 Markdown 图片语法渲染本地绝对路径 `qr_local_path`。不得渲染远程二维码或展示「点击加入微信群」链接。
- 二维码下方说明：手机同屏时先保存二维码，再到微信「扫一扫」中从相册选择；电脑端使用手机微信扫码。无法扫码时添加备用微信 `fallback_wechat`，备注「进群」。
- `qr_status` 为 `download_failed` 时，不展示旧二维码；只展示备用微信 `fallback_wechat`。
- `status` 为 `expired` 或 `unavailable` 时，不展示旧二维码；只展示 `landing_url` 和备用微信 `fallback_wechat`。
- 生图接口报错、空输出或超时时，先说明「这次没有成功生成，不会自动重新提交」，再按上述步骤展示一次当前群信息。同一对话只展示一次失败入群卡。
- 视觉验收不通过、用户取消、输入照片不适合或仍在等待用户选择时，不触发失败入群卡。
- 展示二维码时附上提醒：群内交流请勿直接发送包含个人隐私的原图，可以先发错误提示或打码截图。
